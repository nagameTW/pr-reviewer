Tests — three tiers, area=test. (a) CRITICAL: the diff weakens CI — a deleted test file, a skip/xfail/only added, a coverage floor lowered, a workflow step removed. Confirm in the diff that the line really disables a test or lowers a floor before you report CRITICAL: a .skip( call in ordinary code is not one. (b) HIGH: a bug fix with no test that would have failed before the fix — name the test file and line that should exist. (c) MEDIUM: everything else — a new feature under-covered, an assertion too weak to notice a break, a fixture that never reaches the branch, tests that would not fail if the code actually broke, new tests that need a live external service without being marked or skipped as integration tests. Type-only annotations, imports, behavior-preserving refactors, dead-code deletion, and config/doc-only edits are NOT behavior changes — never demand tests for them (a coverage tool reads ~0% on such diffs by nature; that is expected, not a finding).

The words above, spelled out: "skip" and "xfail" mark a test to be skipped or expected to fail (pytest's @pytest.mark.skip and @pytest.mark.xfail, unittest's @skip, Jest and Mocha's it.skip and xit); "only" runs one test and silently drops the rest (it.only, describe.only, fit, fdescribe); a coverage floor is the minimum coverage percentage CI enforces (for example --cov-fail-under, coverageThreshold, fail_under in .coveragerc).
