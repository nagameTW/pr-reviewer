AI-agent security — applies when the diff touches code that sends content to an LLM, exposes tools to one, or acts on its output; otherwise skip it silently. Judge against the two OWASP lists below. Both start from the premise that the model will sometimes be fooled, so judge the code around it by what a fooled model could then reach. The six rules that matter most: (a) prompt injection, LLM01:2026 and ASI01 — a model has no hard line between instructions and data, so any text the application did not write (a user message, a fetched page, a file, a retrieved passage, a tool result) can steer it; a finding is such text written into the instructions themselves (a system or planner prompt assembled from inbound content) or mixed into the prompt with nothing to mark where it came from, and also a path where output steered this way can set off an action that no check outside the model stops; (b) sensitive information disclosure, LLM02:2026 and LLM08:2026 — whatever reaches the model's context can come back out, so a secret or credential in a prompt, a system prompt or a tool description, personal data the task does not need sent to an outside provider, or full prompts and replies kept in logs or traces, is a finding; (c) excessive agency, LLM03:2026, ASI02 and ASI03 — a tool with more functions or permissions than its task needs, one that acts under a shared service or admin identity instead of the user's own, or a high-impact or irreversible step taken with no person approving it, is a finding (item 10 covers tool definitions in detail); (d) memory and retrieval, ASI06 and LLM09:2026 — content kept for later use (agent memory, conversation summaries, a vector index) is only as trustworthy as where it came from, so storing it with no check and no record of its source, one store shared across users or tenants with no scope filter inside the query, or the agent's own output saved back as trusted memory, is a finding; (e) improper output handling, LLM10:2026 — treat the model as one more untrusted user: its reply gets the validation and the context-specific encoding that the code receiving it would give user input (the LLM10 entry below lists where this goes wrong); (f) unbounded consumption, LLM06:2026 — an LLM or tool call with no timeout can hang a run while it keeps costing, and that is the one resource-exhaustion case the denial-of-service exclusion on the "Do NOT report" list does NOT cover, so it is a finding. Map code-level findings to CWE where it sharpens the report; do not invent a CWE id you are unsure of.

How to use the reference lists below. The IDs and names are OWASP's; each explanation and each "In a diff" pattern is this checklist's wording. A pattern is a place to look, never a finding by itself. When a finding matches an entry, cite the ID with its year (LLM06:2025 and LLM06:2026 are different risks). Do not cite an ID that is not listed here. Rate limits, quotas, cost caps and retry caps appear below because the standards list them, but they are on the "Do NOT report" list: of those patterns, only a missing timeout (2b(f)) is a finding.

OWASP Top 10 for LLM Applications 2026 — risks in applications built on large language models (https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/, CC BY-SA 4.0).
- LLM01:2026 Prompt Injection. Anything the model reads (user text, retrieved documents, tool results, images, memory) can change what it does, because the model has no hard line between instructions and data. In a diff: untrusted content spliced into a prompt by string formatting with no delimiting or label; output of that prompt able to trigger a tool with no policy check.
- LLM02:2026 Sensitive Information Disclosure. The system reveals secrets, personal data or another user's data through answers, tool arguments, logs, reasoning traces or embeddings. In a diff: secrets or personal data put into a prompt or retrieval context unredacted; prompts or completions logged verbatim; retrieval not filtered by the caller's permissions.
- LLM03:2026 Excessive Agency. The model has more tools, permissions or autonomy than the task needs, so a wrong or manipulated output becomes a harmful action. In a diff: a new broad tool (run a shell command, fetch any URL, run any SQL); tools running under a service or admin credential; delete, send, pay or merge with no human confirmation.
- LLM04:2026 Supply Chain. Third-party models, adapters, datasets and ML libraries may be vulnerable, tampered with, or not what they claim. In a diff: a model, adapter or dataset fetched by name or by a mutable tag such as latest instead of a pinned revision or digest; a downloaded model artifact used with no hash or signature check; a pickle-format model file from outside trusted because a safe-loader flag is set (torch.load's weights_only has itself been bypassed, CVE-2025-32434).
- LLM05:2026 Data and Model Poisoning. Training, fine-tuning, embedding or retrieval data is corrupted, so the model carries a backdoor or a bias while looking normal. In a diff: an ingestion or fine-tuning job reading from user-writable or external sources with no provenance or checksum; scraped content written straight into a training set or vector store.
- LLM06:2026 Unbounded Consumption. Nothing caps how much inference a caller can trigger, which allows outages, runaway cost, or copying the model through mass queries. In a diff: a model call with no max_tokens, timeout or per-user quota; an agent loop with no step or budget limit; batch or recursion size set by the client.
- LLM07:2026 Misinformation. The model produces wrong or invented content that looks credible, and a person or program acts on it. In a diff: model output driving a decision or tool call with no grounding or check; a package or API the model suggested installed or called without checking it exists.
- LLM08:2026 Hidden Context Exposure. Context meant to stay hidden (system prompt, developer rules, tool schemas, retrieved policy) can be extracted; it is a vulnerability when that context holds secrets or is relied on as a security control. In a diff: keys, connection strings or internal URLs in a system prompt or tool description; an authorization rule enforced only by prompt text instead of code.
- LLM09:2026 Vector and Embedding Weaknesses. The similarity-search layer (retrieval, vector memory, semantic caches) can mix tenants, be manipulated, or leak source text. In a diff: a tenant or permission filter applied to the results after the similarity search instead of inside the index query; a tenant scope taken from the client; raw similarity scores returned to the caller; external and internal content written into one index with nothing keeping them apart; embeddings kept after their source document is deleted.
- LLM10:2026 Improper Output Handling. Model output is passed on without validation or encoding and becomes cross-site scripting, injection, SSRF or code execution; insecure code written by an assistant counts too. In a diff: model output sent to eval, exec, a subprocess, an SQL string, innerHTML, or a Markdown renderer that allows raw HTML or remote images; a URL from the model fetched by the server.

OWASP Top 10 for Agentic Applications 2026 — risks that appear once a model plans and acts through tools, memory and other agents (https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/, CC BY-SA 4.0).
- ASI01 Agent Goal Hijack. Instructions planted in content the agent reads (documents, email, tool results, other agents' messages) redirect its goal or plan. In a diff: a planner or system prompt built by concatenating inbound content; no check that the plan still matches the user's request before acting.
- ASI02 Tool Misuse and Exploitation. The agent uses tools it is allowed to use, in harmful ways: deleting data, over-calling a costly API, sending data out through an allowed channel. In a diff: a tool taking free-form arguments (raw SQL, any URL, a shell string) instead of typed, validated ones; no per-tool rate or cost cap; output of a read tool fed to a send or write tool with no policy gate.
- ASI03 Identity and Privilege Abuse. The agent acts with inherited or cached credentials beyond what the current user and task allow. In a diff: a shared admin or service token instead of a per-user, scoped, short-lived one; credentials kept in memory or prompts; the user's full token passed to a sub-agent.
- ASI04 Agentic Supply Chain Vulnerabilities. Components the agent loads, often at runtime (tools, plugins, MCP servers, remote agents, prompt templates), may be malicious or altered. In a diff: an MCP server or plugin added unpinned (@latest, a bare URL); a tool manifest fetched at runtime with no hash or signature; a remote agent registered without verification.
- ASI05 Unexpected Code Execution (RCE). The agent writes or triggers code that runs on the host. In a diff: generated code run through eval, exec or a subprocess outside a sandbox; a code-interpreter tool with network and file-system access; shell=True on a string derived from model output.
- ASI06 Memory & Context Poisoning. False or malicious content planted in what the agent stores and reuses (memory, summaries, retrieval, shared context) corrupts later decisions. In a diff: memory written with no validation or provenance tag; memory shared across users or tenants; recalled memory inserted as trusted instructions; no expiry.
- ASI07 Insecure Inter-Agent Communication. Messages between agents lack authentication, integrity or validation, so they can be spoofed, altered or replayed. In a diff: agent-to-agent calls over plain HTTP or an unauthenticated bus; the receiver acting on fields with no schema or sender check.
- ASI08 Cascading Failures. One fault (a hallucination, bad input, poisoned memory, a broken tool) spreads across linked agents and workflows. In a diff: one agent's output fed straight into another agent or an automation with no validation step; no retry cap, circuit breaker or stop switch.
- ASI09 Human-Agent Trust Exploitation. People over-trust a fluent agent and approve harmful actions. In a diff: an approval prompt that shows the agent's summary instead of the actual action and parameters; approve-all or default-yes confirmations; an agent allowed to ask users for credentials or payment.
- ASI10 Rogue Agents. An agent drifts from its intended scope and acts harmfully while each single action looks legitimate. In a diff: no action allowlist enforced outside the model; no audit log tying each action to a task and a person; agents able to start agents or edit their own instructions.
